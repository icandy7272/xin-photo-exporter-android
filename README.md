# 鑫时光集 Android 原图导出器

一个独立的、仅处理用户自己账号内容的本地导出工具。项目利用 MuMu 中已登录的“鑫时光集家长版”、ADB 和 App 自身输出的原图资源地址，将原图验证并导出到 Mac。

当前已实现三个样本的原图直下验证，以及“手动滚动 + 流式采集 + 确认后批量下载”的第一版可用流程。不会进行云端 AI 处理或账号范围之外的访问。

## 当前状态

- 技术可行性已通过只读探测验证。
- 技术路线经过 Review 后已精简为个人本地 Smoke MVP。
- 已实现默认只读 dry-run，以及需要明确参数才会执行的三张样本下载。
- 已实现手动批量采集、稳定续跑文件名、两轮失败重试和按记录日期整理。
- 已实现可选的自动滚动采集：自动滑动相册，滚到列表底部（画面不再变化）时停止。

## Smoke 验证

先启动 MuMuPlayer，在“鑫时光集家长版”中登录自己的账号并浏览照片列表，让 App 将当前照片信息加载到日志。然后在仓库根目录运行：

```bash
python3 tools/export_originals.py
```

该命令只检查 MuMu、目标 App 和候选原图数量，不创建目录、不下载照片。确认结果后，明确执行三张样本下载：

```bash
python3 tools/export_originals.py --execute
```

工具只下载前三个有效候选，输出到被 Git 忽略的 `build/direct-original-smoke/<时间戳>/`。它不会保存 logcat 或 URL 列表，也不会把 URL 写进文件名或终端输出。

请在 macOS 中人工打开三个样本，检查内容归属、能否正常打开、尺寸和画质。照片像素与 EXIF 可能包含敏感信息，验证后请手动删除样本目录。

## 手动批量导出

先启动 MuMuPlayer 和已登录本人账号的“鑫时光集家长版”，然后运行：

```bash
python3 tools/export_originals.py batch
```

工具会先读取当前 App 进程仍保留在 logcat 中的候选，然后持续监听新日志。此时在 MuMu 中手动滚动照片列表；终端只显示唯一候选数量，不显示 URL。

滚动完成后按 `Ctrl-C` 停止采集。工具会显示候选总数：

- 准确输入 `DOWNLOAD`：开始批量下载；
- 直接回车、输入其他内容或再次中断：取消，不创建照片文件。

下载输出固定在：

```text
build/originals/
```

文件名示例：

```text
2026-06-04_<稳定URL哈希>.jpeg
```

工具会把 Finder 创建日期和修改日期设为记录日期当天中午，以便按成长日期排序。没有有效日期的候选使用 `unknown-date_` 前缀，但仍然下载。

批量行为：

- 顺序下载，不并发；
- 单张失败不阻塞其他照片；
- 首轮结束后，失败项最多再重试两轮；
- 已有且通过最小 JPEG 校验的稳定目标直接跳过网络请求，并重新尝试设置日期；
- 遗留 `.part` 会删除后重下；损坏最终文件只有在新文件完整验证成功后才被替换；
- 下载中按 `Ctrl-C` 会清理当前 `.part`、保留已完成照片并停止后续请求。

完整 URL 和失败队列只存在于当前 Python 进程内存，不写日志或清单。因此下载能够通过稳定文件名续跑，但采集过程不能断点续传：进程退出后需要重新滚动列表。当前版本只能确认“本轮发现的候选已完成”，不能证明账号中的每一张照片都已经被发现；列表覆盖判断属于下一阶段。

## 自动滚动采集（可选）

不想手动滚动时，可以让工具自动滚动相册：

```bash
python3 tools/export_originals.py batch --auto-scroll
```

工具会先读取屏幕分辨率，然后用 `adb shell input swipe` 自动向上滑动列表，每次滑动后 dump 一次 logcat 并合并新候选（终端只显示唯一候选数量，不显示 URL）。**停止判据是「列表已经滚到底」**：每次滑动后对屏幕截图算一次哈希，当**连续若干次滑动画面都不再变化**时判定到底并停止；也可以随时按 `Ctrl-C` 提前结束。这样即使某一段照片已缓存、暂时不吐新 URL，也会一路滑到真正的底部（沿途触发后续未缓存页加载并采集），不会因为「暂时没有新候选」就提前停下。停止后进入与手动模式相同的 `DOWNLOAD` 确认与批量下载流程。

关于截图：截屏字节**只在内存中用于算一次哈希、判断画面是否还在滚动**，绝不写盘、不打印、不外传，只保留 32 字节的不可逆摘要，符合「照片只在本机处理」的隐私原则。

自动滚动只驱动 UI 滑动与采集，不会停止 App、删缓存或清 logcat。**已缓存的照片滑过时不会再吐原图地址**，因此要采到这些照片的 URL，需先用缓存准备流程（清缓存重启）再自动滚动——自动滚动负责「滚到底」，缓存准备负责「让每张重新吐 URL」，两者配套。

已知限制（第一版有意取舍，真机实测）：

- **超大相册可能卡顿甚至崩溃**：一路滚动会让 App 持续加载几百张高清图，实测滚动越来越卡、翻页越来越慢，内存吃紧时 App 可能 OOM 崩溃；崩溃会中断本次采集（且采集不可续采，需重来）。因此本功能对**中小相册和「最新那批」可靠**，回溯很老（如两三年前）的照片可能采不全。
- **到底判据基于「画面连续不变」**：真机上曾因偶发两帧相同而**提前误判到底**；现已要求**连续 `max_stable_screens`(默认 6) 次滑动画面都不变**（配合 2.5s settle）才停，明显更稳，但超大相册仍不保证一定滚到真正底部。`max_swipes` 为安全上限；截图连续失败时不会误判到底、而是滑到上限为止。
- **采集不可跨运行续采**：进程退出（含崩溃）后需要重新滚动。
- 严格的「列表覆盖率」证明（逐项核对账号全量）属于后续迭代。
- **可靠的全库导出**需绕开会崩的 UI、走后端 API；该接口需另行获取，属独立后续工作（见设计文档）。

## 直连 API 全量导出（推荐，全库）

绕开会崩的模拟器 UI，直接调后端 feed 接口分页拿全库**原图 + 视频 + 帖子正文**：只拉 JSON、不渲染图片，低内存、能翻到最老的内容。接口经一次性 MITM 抓包逆向得到（见 [docs/mitm-capture-runbook.md](docs/mitm-capture-runbook.md)）。

前置：MuMuPlayer 运行、「鑫时光集家长版」已登录本人账号。然后运行：

```bash
python3 tools/export_originals.py api
```

工具会：

1. 从 App 的 `shared_prefs` 读取登录态（`accessToken`、`album_child_id`）；
2. 翻页调用 `moment/FamilyMoment/v2/getPageMomentList`（`counter` 游标 + `hasMore`），采集每条帖子的**正文、日期、照片（`pictureURLs`）、视频（`videoUrl`）**；终端只显示帖子/原图计数；
3. `hasMore=false` 到底自动停止，也可随时 `Ctrl-C` 提前停并保留已采集部分；
4. **采集完立刻保存正文**（下载媒体前就写好，网络差也不丢文字）：
   - `build/moments.jsonl`：每条帖子一行 JSON（正文 + 对应照片/视频**文件名**，不含 URL），可机器处理；
   - `build/captions.txt`：`[时间] 正文` 可读文本（仅有正文的帖子）；
5. 与批量模式相同的 `DOWNLOAD` 确认，下载**照片**到 `build/originals/`、**视频**到 `build/videos/`（文件名 日期+哈希，按记录日期整理）；取消下载也不影响已保存的正文。

参数：

- `--counter <值>`：首页为空（游标语义变化）时指定起始游标，默认从最新开始。
- `--no-videos`：只下照片、不下视频（正文与清单仍会保存）。网络差时可先只导照片，视频等网好再单独跑。

隐私：登录 token 只在运行内存中用于调用**本人账号**接口，**绝不打印、不写日志、不进 Git**；只取帖子自己的 `pictureURLs`/`videoUrl`，不碰头像/logo；清单与正文只写本地 `build/`（已 gitignore）、且只用文件名关联、不写 URL。

## 隐私原则

- 完整原图 URL 只在运行内存中短暂存在。
- URL、照片、EXIF和账号信息不得写入 Git、普通日志或报告。
- 所有照片处理均在用户本机完成。
