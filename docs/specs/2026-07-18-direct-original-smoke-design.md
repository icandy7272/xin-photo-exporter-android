# Android 原图直下 Smoke MVP 设计

## 目标

用最小成本验证“从 MuMu 中已登录的鑫时光集家长版读取 App 日志里的原图地址，并直接下载原始 JPEG”这条路线。

第一版只下载三个样本。自动检查文件可用性，最后由用户人工确认照片内容和画质。验证通过后立即进入“流式 logcat + 手工滚动 + 批量下载”，不在 Smoke 阶段做生产级加固。

本项目与原有 Mac/iPhone 照片助手完全独立。

## 已验证事实

- MuMu 是 Android 12 / API 32 / ARM64。
- 鑫时光集家长版包名是 `com.childfolio.family`，当前版本为 `1.9.17`。
- App 日志会输出成对的“原图地址”和“压缩地址”。
- 列表加载更多内容时，日志中的唯一原图地址曾从 67 增加到 114。
- 已观察到的原图地址均使用：

  ```text
  https://cdn-mctchildfoliocn.childfolio.net/...jpeg
  ```

- 一个样本地址已经通过 HTTP 200、`image/jpeg` 和单字节 Range 请求验证。
- Android UI 树暴露 `rv_moment` 等资源 ID；后续可以用 UI Automator 只控制列表滚动，不需要视觉识别。

## 第一版包含

实现一个仅依赖 Python 3 标准库和 MuMu 自带 ADB 的命令行工具：

1. 找到唯一运行中的 MuMu 设备和 ADB 端口。
2. 找到包名 `com.childfolio.family` 的当前主进程 PID。
3. 读取该 PID 当前仍保留在 logcat 环形缓冲中的日志。
4. 在内存中提取标记为“原图地址”的 URL。
5. 使用标准 URL 解析器验证：
   - scheme 是 `https`；
   - hostname 精确等于 `cdn-mctchildfoliocn.childfolio.net`；
   - 没有非标准端口；
   - path 以 `.jpeg` 结尾。
6. 保留 URL 原始编码，不自行百分号解码或重新拼接 path。
7. 按日志首次出现顺序去重，选择前三个不同候选。
8. 顺序下载三个 JPEG。
9. 对每个文件做最小完整性验证。
10. 输出脱敏结果，由用户人工打开样本检查。

## 第一版不包含

- 不滚动列表，不触发下一页。
- 不保存完整 logcat、URL列表或失败 URL 文件。
- 不点击照片、下载、分享或保存按钮。
- 不读取 App 私有缓存。
- 不修改存储权限、AppOps、Root或登录状态。
- 不下载视频或压缩图。
- 不导入 Mac“照片”。
- 不做全量、自动滚动、并发、续传、人物检测或复杂排序。
- 不实现生产级 SSRF防御、DNS/IP锁定、目录描述符遍历、信号恢复或废弃任务清理器。

## 用户前置确认

执行真实下载前，界面明确提示用户确认：

- 当前 MuMu 实例和鑫时光集账号属于用户本人，或用户已获授权导出；
- 当前 App 会话没有切换账号；
- 样本可能包含敏感画面和 EXIF，只保存在本机短期检查。

工具不声称能够从 CDN URL 技术证明账号所有权。

## 工具结构

第一版采用单个 Python 入口和少量聚焦模块：

- `mumu.py`：定位 MuMu 工具、运行设备和 ADB 端口；
- `logcat.py`：查询目标 PID并读取当前日志到内存，不落盘；
- `urls.py`：解析、允许列表校验和去重；
- `download.py`：使用关闭代理和重定向的 Python进程内 HTTPS 客户端下载，不把 URL放入外部命令参数；
- `jpeg.py`：执行最小 JPEG验证；
- `cli.py`：dry-run、执行提示、脱敏进度和终态。

模块可以合并，只要职责和测试边界保持清楚；不为了文件数量而拆分。

## URL 与隐私规则

- 只接受日志中明确标记为“原图地址”的 HTTPS URL。
- hostname 必须精确匹配已知 CDN，不接受相似域名或其他子域。
- Python标准库 opener 显式禁用环境和系统代理，避免完整 URL 被转交给第三方代理。
- 关闭自动重定向；任何 3xx 视为当前样本失败。
- URL 只存在于当前 Python进程内存，不写入文件、报告、终端或命令行参数。
- 不打印底层异常中可能包含的完整 URL；错误转为简单分类，例如“网络失败”“HTTP状态异常”“JPEG验证失败”。
- 不上传 URL、照片、哈希或元数据到第三方。
- 不枚举、猜测或推导其他资源地址。

这些规则用于避免个人照片链接被无意传播，不扩展成面向恶意本地用户的安全产品。

## 下载和验证

### 下载行为

- 默认 dry-run，不下载文件，只显示设备、App、唯一候选数量和计划样本数。
- 只有显式 `--execute` 才发起三个完整 GET。
- 顺序下载，不并发。
- 每个请求使用一个普通的 120 秒标准库网络超时；Smoke阶段不另外实现精确的请求总墙钟计时器。
- 单文件最多 50 MiB，超过立即停止该样本。
- 禁止自动重定向。
- 先写 `.part`，验证成功后改名为 `.jpeg`。
- 第一版每个样本不自动重试；失败直接报告，避免扩大 Smoke 行为。

### 最小 JPEG验证

- HTTP状态为 200；
- Content-Type主类型为 `image/jpeg`；
- 文件大小大于 1 KiB且不超过 50 MiB；
- 文件以 JPEG SOI `FF D8` 开始；
- 计算内容 SHA-256；
- 三个成功样本的内容哈希如有重复则明确报告，但 Smoke阶段不选择第四张替补。

第一版不自写 JPEG marker或尺寸解析器。现场验收通过 macOS正常打开文件来确认实际可解码性，并由用户人工查看尺寸和画质。

程序只能报告“下载了 App 标记为原图地址的有效 JPEG”，不能报告“已技术证明是上传源文件”。画质由用户对已知照片人工确认。

## 输出

固定输出目录锚定仓库根目录，而不是调用者当前工作目录：

```text
<repository-root>/build/direct-original-smoke/<timestamp>/
```

成功文件：

```text
sample-01.jpeg
sample-02.jpeg
sample-03.jpeg
```

- 仓库根目录由脚本/项目文件的真实位置推导；从其他工作目录启动也必须写入同一仓库的 `build/`。
- 启动时做一个简单前置检查：仓库 `.gitignore` 存在并覆盖 `build/`；不满足则停止，不实现生产级 Git或路径竞态检查。
- 使用 `umask 077`，目录仅当前用户访问。
- 输出目录由工具创建；已存在时换一个新 timestamp 后缀，不覆盖已有样本。
- `.part` 在正常失败时删除。
- 结果只在终端显示脱敏计数、字节数、文件 SHA-256 和目录路径。
- 不生成包含 URL 的 `feed.log`、`urls.txt`、`fails.txt` 或报告。
- `build/`、常见图片扩展名和潜在 URL日志文件由 `.gitignore` 排除。

用户确认后可手工删除整个 timestamp目录。工具不自动删除已经成功下载的样本。

## 错误处理

以下情况停止或报告失败，不显示完整 URL：

- MuMu 未运行或出现多个无法判断的设备；
- 鑫时光集进程不存在；
- 当前日志中合格唯一 URL少于三个；
- URL格式或域名不符合规则；
- DNS、TLS或网络超时；
- HTTP非200、发生重定向或内容类型错误；
- 超过文件上限；
- JPEG魔数无效或内容重复；
- 输出目录不可写。

若三张中任一张失败，保留其他已经验证成功的样本，并明确显示成功数与失败数，方便判断路线是否可用。第一版不自动寻找第四张替补。

## 测试

离线测试只覆盖决定 Smoke可靠性的核心：

- 原图与压缩地址混合时只提取原图；
- host精确匹配，拒绝相似域名、HTTP和非 JPEG path；
- 标准百分号编码 path能够原样保留；
- URL去重和前三个选择顺序；
- dry-run不调用下载器、不产生 JPEG；
- URL不进入stdout、stderr和文件名；
- HTTP状态、Content-Type、大小上限、SOI和重复内容报告；
- 标准库 opener明确禁用代理和重定向；
- 从任意当前工作目录运行仍写入仓库根目录下被 `.gitignore` 覆盖的 `build/`；
- `.part` 成功改名与正常失败清理。

网络测试使用本地合成 JPEG和假传输层，不使用真实照片或真实 CDN URL。

## 现场验收

1. dry-run发现至少三个唯一候选，不产生图片。
2. 用户确认账号和敏感内容提示。
3. 使用 `--execute` 下载三个样本。
4. 终态报告成功数、失败数和输出目录，不显示 URL。
5. 成功样本能够由 macOS正常打开，并由人工查看实际尺寸。
6. 用户检查样本属于当前账号，并判断画质是否符合“原图”预期。
7. 样本和潜在日志文件没有进入 Git。

## 验证通过后的下一步

下一阶段优先实现最小批量版本：

```text
流式读取 logcat
        +
用户手工滚动照片列表
        ↓
内存提取与去重原图 URL
        ↓
边发现边下载，失败继续
        ↓
输出成功 / 重复 / 失败计数
```

流式读取用于避免 logcat环形缓冲覆盖早期 URL。手工批量版跑通后，再决定是否增加 UI Automator自动滚动、续跑账本、Mac“照片”导入、视频跳过和本地人物检测。
