# Android 原图直下验证 MVP 设计

## 目标与技术声明

从用户当前已登录的 MuMu“鑫时光集家长版”进程日志中预选恰好三个不同的“原图地址”，对每个地址最多发起一次 HTTPS GET，将三个 JPEG 下载到隔离的本地测试目录并验证文件完整性。用户最后人工确认样本内容和画质。

自动化只能声明：工具下载并验证了 App 日志中标记为“原图地址”的 JPEG。程序不能仅凭 MIME、尺寸或哈希证明它一定是上传时的源文件；“原图画质”由用户对照已知照片人工确认。

本项目与原有 Mac/iPhone“鑫时光集照片助手”完全独立，不使用它的源码、Bundle ID、权限、构建产物或 Git 历史。

## 已验证事实

- MuMu 设备为 Android 12（API 32）、ARM64。
- 鑫时光集家长版包名为 `com.childfolio.family`，versionName `1.9.17`，versionCode `104`，target SDK 35。
- App 日志明确、成对输出“原图地址”和“压缩地址”。
- 列表继续加载后，日志中的唯一原图地址从 67 增加到 114。
- 已发现地址均来自 `cdn-mctchildfoliocn.childfolio.net`，以 `.jpeg` 结尾且不带查询参数。
- 一个原图地址的 HEAD 请求返回 HTTP 200；单字节 Range 请求返回 HTTP 206；内容类型为 `image/jpeg`。
- Android UI 树暴露列表和大图资源 ID，后续可使用 UI Automator 滚动，无需视觉识别。
- 正式路线不依赖 Root、私有缓存或 Android 的“保存到内存卡”功能。

## MVP 包含

- 连接当前正在运行的唯一 MuMu 设备。
- 锁定并重复核验唯一的 `com.childfolio.family` 主进程、UID、版本和设备身份。
- 从该 PID 的现有 logcat 中解析符合会话时间边界的“原图地址”。
- 使用严格 URL 语法和精确 CDN 允许列表。
- 在任何网络访问之前确定性预选恰好三个候选。
- 显式执行时，对每个预选候选最多发起一次完整 GET；全程最多三次 GET。
- 验证 HTTP、内容类型、JPEG 结构、文件大小、像素尺寸和 SHA-256。
- 生成不含完整 URL、URL 哈希、照片内容和 EXIF 的脱敏报告。
- 用户人工打开样本确认内容和画质。

## MVP 不包含

- 不滚动列表，不触发新页加载。
- 不点击照片、下载、分享或保存按钮。
- 不使用视觉识别或 UI Automator 派发输入。
- 不读取 App 私有数据或缓存。
- 不清空 logcat，不修改权限、AppOps、登录状态或 Root 状态。
- 不下载压缩图或视频。
- 不导入 Mac“照片”App。
- 不做全量、并发、续传、人物识别、候选替补、网络重试或 URL 枚举。

## 用户授权与会话来源

工具无法仅凭 CDN URL 独立证明账号所有权。执行前用户必须确认：

1. 当前 MuMu 实例和鑫时光集账号由用户本人所有，或用户被明确授权导出；
2. App 本次启动以来没有切换账号；
3. 用户已在确认账号后手工完全退出并重新启动过鑫时光集，使来源日志具有清晰进程边界；
4. 用户授权下载本次预选的三个样本。

真实执行必须同时提供 `--execute` 和 `--attest-current-account`；缺一即为零网络退出。该 attestation 只说明用户作出确认，不声称工具已技术证明账号所有权。

## 设备、包和进程身份

只接受：

- `mumutool info` 返回恰好一个 running 设备；
- ADB 中恰好一个匹配该实例和端口的 transport；
- 设备 serial、MuMu instance index 和 ADB port 在运行期间不变；
- 包名精确为 `com.childfolio.family`；
- versionName 精确为 `1.9.17`，versionCode 精确为 `104`；
- 包 UID 唯一；
- 恰好一个主进程，其 `/proc/<pid>/cmdline` 精确为包名且 UID 等于包 UID；
- PID 和 `/proc/<pid>/stat` 的进程启动时间在整个预检期间不变。

日志使用带 epoch 时间和稳定输入序号的格式。只接受时间不早于该精确进程启动时间的记录。数字 PID 本身不足以建立会话来源；执行网络请求前必须再次核验 serial、实例、端口、版本、UID、PID、cmdline 和进程启动时间。任何漂移均零网络停止。

若 App 允许同进程内切换账号，则技术上无法从日志判断切换边界，因此用户手工重启与 attestation 是本 MVP 的强制前置条件。

## 日志采集边界

- 通过 MuMu 自带 ADB 读取目标 PID 的现有 logcat；不清空日志，不持续后台监听。
- 原始 logcat 仅通过匿名管道进入解析器，不写临时文件。
- 最多读取 8 MiB 或 50,000 行，以先达到者为准；超限失败关闭。
- 最多接受 5,000 个合格但未去重候选；超限失败关闭。
- 工具不试图删除 App 已经写入 Android logcat 的 URL，但不得产生任何新的完整 URL 持久化。

## 严格 URL 解析契约

只接受精确日志标记后的一枚 URL token：

```text
原图地址::https://cdn-mctchildfoliocn.childfolio.net/<path>.jpeg
```

要求：

- marker 必须精确匹配；URL 后只允许空白，存在其他尾随内容即拒绝整行；
- URL 总长不超过 2,048 ASCII 字节；
- 不允许空白、控制字符、反斜杠、非 ASCII host、userinfo或 fragment；
- scheme 必须精确为小写 `https`；
- host 经标准化后必须精确为 `cdn-mctchildfoliocn.childfolio.net`；不接受其他子域；
- port 必须省略或为 443；
- query 必须完全不存在，包括空的 `?`；
- path 必须为绝对路径，只含 ASCII 字母、数字、`/._~%-`；
- path 必须以小写 `.jpeg` 结尾；
- 不允许空 segment、`.`、`..`、无效百分号转义、百分号编码的 `/` 或 `\`；
- 解析后重新序列化不得改变任何安全相关组件；后续请求必须使用同一个规范化对象；
- 按规范化完整 URL 在内存中去重，不持久化 URL 或其稳定哈希。

压缩地址和其他日志 URL 全部忽略。

## 候选选择与请求预算

对符合进程边界的记录按 `(epoch timestamp, log input sequence)` 升序排列，保留每个规范化 URL 的首次出现，选择最早三个。

在网络开始前冻结这三个候选。执行具有不可突破的运行预算：

- 恰好三个预选候选；
- 每个候选最多一次 GET；
- 全程最多三次 GET；
- 零 HEAD、零 Range、零重试、零第四候选；
- 任一候选失败、内容重复或验证失败，整个运行失败，不替补。

## 零网络 dry-run

没有同时提供 `--execute --attest-current-account` 时：

- 必须发起 **零次** HTTP(S) 请求；
- 不构造或调用下载器；
- 不执行 HEAD、Range、部分 GET、重定向探测、DNS 解析或连通性检查；
- 参数非法、前置条件失败、设备/进程漂移等路径同样必须零网络。

测试传输层在任何调用时立即失败，并断言上述所有路径的请求计数精确为零。

## HTTPS 传输与 SSRF 防护

MVP 使用进程内网络实现，不将 URL 放入命令行参数或环境变量，也不调用 `curl` 等外部下载器。

- 不读取或使用 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、平台代理、`.netrc` 或系统凭据存储；
- 不自动跟随重定向；本 MVP 允许重定向次数固定为 `0`，任何 3xx 都失败；
- 每个候选在连接前只进行一次 DNS 解析；
- 所有解析结果必须是全局可路由地址，拒绝 IPv4/IPv6 的 loopback、private、link-local、multicast、unspecified、reserved和documentation范围；
- 从已验证结果中确定性选择一个地址，连接必须固定到该地址，不允许第二次未验证解析；
- TLS SNI、主机名验证和证书验证仍使用精确 CDN hostname；
- 禁止明文 HTTP 和 TLS 验证降级；
- 连接超时 10 秒；从连接开始到完成的总墙钟超时 60 秒；
- 响应头上限 64 KiB；不读取或记录响应体错误页；
- 只接受 HTTP 200；
- `Content-Type` 主类型大小写不敏感地等于 `image/jpeg`，允许合法参数；
- 单文件上限 50 MiB，三文件总上限 150 MiB；无论 `Content-Length` 如何，流式读取一旦超过上限立即中止。

HTTP/TLS库的调试日志、请求转储和响应转储全部禁用。所有底层异常转换为固定的脱敏错误枚举，不渲染异常对象、请求对象、Location、响应体或完整路径。

## 文件验证边界

每个文件要求：

- 大小至少 1 KiB，至多 50 MiB；
- 以 JPEG SOI 开始，以最后一个合法 EOI 结束，EOI 后不允许额外数据；
- 结构解析成功，不接受截断或越界 segment；
- 宽、高均在 64 至 20,000 像素之间（含边界）；
- 总像素不超过 100,000,000；
- 解码/结构验证墙钟上限 10 秒；
- 计算内容 SHA-256；三个内容哈希必须互不相同。

验证器不输出或结构化记录 EXIF、位置、拍摄时间、设备信息或预览。原 JPEG 字节可能自带敏感 EXIF，样本保留时该 EXIF 也会保留，工具必须在执行前明确警告。

## 输出目录与防覆盖

仓库根目录由脚本自身的规范化真实路径和受信仓库标记确定，不使用任意当前工作目录。固定父目录为：

```text
<repo>/build/direct-original-smoke/
```

要求：

- 运行前设置 `umask 077`；
- 父目录到目标目录的每个组件均用 `lstat` 验证不是 symlink；
- run ID 由 UTC 时间和 128 位随机数组成，不接受用户输入、不含路径分隔符；
- 新运行目录必须独占创建，已存在即失败；目录模式创建并复核为 `0700`；
- 文件固定命名为 `sample-01.jpeg`、`sample-02.jpeg`、`sample-03.jpeg` 和 `report.json`；
- `.part` 与目标均独占创建、禁止跟随 symlink、禁止替换已有文件；
- `.part` 到目标的 rename 只能发生在同一已验证运行目录；
- JPEG与报告模式创建并复核为 `0600`。

任一下载、验证、取消、信号或提交步骤失败时，删除本次运行的全部 JPEG 和 `.part`，只允许留下不含敏感值的失败报告。成功目录必须恰好包含三个普通 JPEG、一份报告和零 `.part`。

报告只记录：运行时间、包名/版本/PID、run-local样本序号、HTTP状态、内容类型、文件名、字节数、像素尺寸、内容SHA-256和固定脱敏错误码。不得记录 URL、URL 哈希、响应头原文、EXIF或个人信息。

## URL 泄露防护

App 已经把 URL 写入 Android logcat，本工具不能撤销或清理该既有披露。本工具保证不产生新的完整 URL 持久化：

- 不把 URL 写入磁盘、报告、终端、UI、文件名、命令行参数或环境变量；
- 不启动可能在进程列表中暴露 URL 的外部下载器；
- 不生成原始日志文件、HTTP debug日志、traceback、crash dump或请求转储；
- 所有错误只通过闭集枚举报告；
- 测试使用带敏感 path/query 的 sentinel URL，并扫描 stdout、stderr、报告、文件名、临时文件、异常路径和仓库文件，确保 sentinel 的各敏感子串均不存在。

## 运行方式

独立命令行 smoke 工具：

- 默认或只有 `--dry-run`：完成设备、包、进程、日志、候选数量和输出路径预检，零网络、零 JPEG；
- `--execute --attest-current-account`：再次核验身份，冻结三个候选，明确显示敏感像素和 EXIF 保留警告，然后按预算执行；
- 不接受输出目录、域名、样本数量、重试次数或并发度等用户可调安全参数。

## 测试与验收

### 离线测试

- 严格日志 grammar、URL 解析、去重、时间/序号排序和精确候选选择；
- 所有 URL 限制在 `limit-1`、`limit`、`limit+1` 的边界；
- dry-run、非法参数和失败前置条件的请求计数均精确为零；
- execute 对冻结的三个候选最多三次 GET；失败或内容重复不选择第四个；
- 零重定向，禁止代理，拒绝所有非全局地址，连接地址与验证结果一致；
- TLS hostname/SNI和证书验证不可降级；
- 字节、尺寸、总像素、头部、日志量、候选数和超时边界均做上下界测试；
- symlink、预创建路径、权限、独占创建、同目录rename、清理和部分失败；
- 成功只留下三个 JPEG 和一份报告；失败不留下 JPEG 或 `.part`；
- 设备、serial、实例、transport、版本、UID、PID、cmdline、进程启动时间漂移均关闭失败；
- sentinel URL 敏感子串不出现在任何捕获输出或文件。

网络测试只使用本地合成 JPEG和注入式假 DNS/传输层，不使用真实 CDN URL或儿童照片。

### 现场 dry-run

找到唯一设备、目标版本/UID/PID和至少三个会话内候选；请求计数为零，不产生 JPEG，输出不含完整 URL。

### 现场执行验收

1. 用户完成账号和授权 attestation。
2. 执行前身份复核通过，恰好冻结三个候选。
3. 最多三次 GET 后，成功时目录中恰好三个验证 JPEG、一份脱敏报告、零 `.part`。
4. 三个文件均可由 macOS 正常打开。
5. 用户用已知照片人工确认内容属于当前账号，并记录“人工原图画质评估通过/不通过”。
6. 仓库内没有完整 URL、样本、报告或未忽略的敏感产物。

## 样本保留与清理

执行前提醒：JPEG包含敏感像素，也可能包含原始 EXIF。样本仅用于短期人工检查，建议确认后立即删除整个 run 目录。工具显示规范化的精确目录，但 MVP 不自动删除成功样本，避免未经确认的数据丢失。

## 后续阶段

本 MVP 通过后再分别设计：UI Automator有限滚动、全量采集与恢复、按组和时间重建顺序、有限并发、导入 Mac“照片”、跳过视频及本地人物检测。以上均不属于本 MVP。
