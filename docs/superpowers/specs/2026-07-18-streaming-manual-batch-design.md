# 鑫时光集流式手动批量导出设计

## 目标

在已验证的 Android 原图直下 Smoke MVP 上增加第一个可实际使用的批量版本：工具读取当前鑫时光集进程的既有 logcat 缓冲区并持续监听新日志，用户在 MuMu 中手动滚动照片列表；停止采集并明确确认后，工具顺序下载本轮发现的全部原图候选。

本阶段追求“所有已发现候选均成功下载或已存在”。它不声称已经技术证明发现了账号中的每一张照片；列表覆盖证明和 UI Automator 自动滚动属于下一阶段。

## 已确认的用户选择

- 使用“先采集、后确认下载”，不边采集边下载。
- 启动时读取当前目标 App PID 的既有缓冲日志，然后持续监听新日志。
- 不清空整个模拟器 logcat。
- 首轮单张失败不阻塞整批；整批结束后在内存中最多重试两轮。
- 不把 URL、完整 logcat 或失败 URL 写入磁盘。
- 使用稳定文件名支持重新采集后的续跑。
- 第一版按 URL 中的日期恢复成长时间线；同一天内部暂不保证精确发帖顺序。

## 非目标

- 不自动滚动列表，不判断是否滚到底。
- 不证明账号照片已经全量覆盖。
- 不读取、抓取或逆向 App 私有接口。
- 不处理视频、压缩图、人物检测或 Mac“照片”导入。
- 不持久化恢复队列、URL 清单或完整日志。
- 不并发下载，不实现复杂调度器。
- 不恢复同一天多个帖子之间的精确时分秒顺序。

## 用户流程

运行：

```bash
python3 tools/export_originals.py batch
```

流程：

```text
发现唯一运行中的 MuMu 与鑫时光集 PID
        ↓
消费该 PID 当前 logcat 缓冲区
        ↓
持续监听该 PID 新日志
        ↓
用户在 MuMu 中手动滚动照片列表
        ↓
内存校验、去重并实时显示唯一候选数量
        ↓
用户按 Ctrl-C 停止采集
        ↓
终止并等待 logcat 子进程退出
        ↓
显示候选数量并要求输入 DOWNLOAD
        ↓
顺序下载全部候选
        ↓
失败项最多再重试两轮
        ↓
输出脱敏终态计数与本地目录
```

采集阶段不创建图片。只有准确输入 `DOWNLOAD` 才发起 GET；回车、EOF 或其他输入均取消。零候选时不显示下载确认，也不创建输出目录。

## 组件与边界

继续使用单个标准库脚本 `tools/export_originals.py`，通过聚焦函数维持测试边界，不为了文件数量拆模块：

- MuMu/ADB 发现：复用现有设备、PID 和 bundled ADB 路径。
- 流式 logcat：构造 PID 定向的 ADB 子进程，逐行读取，支持停止和等待。
- URL 采集器：复用精确 CDN allowlist 和原图标记解析，按首次出现顺序在内存去重。
- 日期与命名：从 URL path 的固定段提取日期并生成稳定目标路径。
- 批量下载器：复用禁代理、拒绝重定向、CA、大小和 JPEG 校验边界，加入已有文件检查、重试和计数。
- 文件时间：使用 macOS `/usr/bin/SetFile` 设置 APFS 创建日期，使用标准文件时间 API 设置修改日期。
- CLI：保留现有 Smoke 默认行为和 `--execute`；新增互不冲突的 `batch` 子命令。

完整 URL 只能存在于当前 Python 进程内存以及 Python 进程内的 HTTPS Request 对象中，不能进入终端、文件名、报告、异常文本或外部命令参数。`SetFile` 只接收本地目标文件路径和日期。

## 流式采集

启动前先完成 MuMu 设备与当前 `com.childfolio.family` PID 检查。流式命令必须使用 MuMu bundled ADB、目标 serial、目标 PID 和 brief 格式。

采集器必须同时覆盖：

1. 子进程启动时返回的当前 PID 缓冲日志；
2. 启动后 App 新产生的日志。

逐行解析时只保留通过 `validate_original_url` 的“原图地址”。压缩地址、其他域名、HTTP、非 JPEG path、query、fragment 和非标准端口继续被拒绝。

每发现一个首次出现的有效 URL，只打印新的唯一候选总数，不打印 URL、路径日期、provider ID 或文件名哈希。重复 URL 不增加计数。

用户在采集阶段按 `Ctrl-C` 时，父进程终止 logcat 子进程并有界等待；必要时升级为 kill，避免后台 ADB 遗留。随后进入确认阶段，而不是把这次中断当作失败。若子进程自行异常退出、目标 PID 消失或 stdout 不可用，则停止并显示脱敏错误，不自动下载。

本阶段不自动重连新的 PID。App 在采集中重启时，用户重新运行 batch。

## 日期、文件名和排序

已观察到原图路径包含：

```text
/moments/images/YYYY-MM-DD/<opaque-name>.jpeg
```

日期解析使用标准 URL parser 的 path，且只接受真实日历日期。日期字段不改变 URL allowlist 判定：URL 合格但日期缺失或无效时，照片仍然下载，避免为排序而漏图。

有日期的稳定文件名：

```text
YYYY-MM-DD_<sha256-of-full-url>.jpeg
```

无有效日期：

```text
unknown-date_<sha256-of-full-url>.jpeg
```

使用完整 64 位十六进制 SHA-256，避免缩短哈希引入无意义的碰撞处理。哈希只用于本地稳定映射，不作为内容完整性哈希。

成功下载后：

- 修改日期设置为对应日期本地时间 `12:00:00`；
- `/usr/bin/SetFile` 可用时，将 APFS 创建日期也设置为同一时间；
- 选择中午以降低时区转换造成跨日的风险；
- 日期设置失败不把有效 JPEG 判为下载失败，但增加“日期设置失败”计数并给出脱敏警告。

重新运行遇到有效已有文件时，仍然根据稳定文件名对应的 URL 日期重新尝试应用修改日期和 APFS 创建日期。这样一次非致命日期设置失败可以在后续运行中自愈；本轮仍失败时照常增加“日期设置失败”计数，但文件继续计为“已存在”。

这种设计保证 Finder 按文件名、创建日期或修改日期查看时能够恢复按天的成长轨迹。当前来源没有帖子时分秒，因此同一天内部不承诺严格发帖顺序。

## 输出与续跑

固定输出目录：

```text
<repository-root>/build/originals/
```

继续要求仓库 `.gitignore` 覆盖 `build/`，并在下载阶段使用 `umask 077`。目录与文件只供当前用户访问。

下载前的目录边界采用确定规则：

- 仓库根目录下的 `build/` 如果存在，必须是当前用户拥有的真实目录，不能是符号链接；其已有 mode 不由工具修改，因为敏感文件仍位于下一层私有目录。
- `build/originals/` 如果不存在，以 mode `0700` 创建；如果存在，必须是当前用户拥有的真实目录、不能是符号链接，且 group/other 权限位必须为 0。
- 工具不自动 `chmod` 或接管不符合要求的已有目录；检查失败时在任何下载前停止并显示脱敏错误。
- 新 JPEG、`.part`、`.invalid-*` 和 `.stale-*` 文件在 `umask 077` 下创建，最终 JPEG 预期 mode 为 `0600`。

重新采集到相同 URL 时会得到相同目标路径：

- 目标不存在：正常下载；
- 目标存在且是当前用户拥有的普通文件：才允许读取和执行 JPEG 校验；通过时计为“已存在”且不发送网络请求；无效时先原样无覆盖保留为 `<name>.invalid-<timestamp>`，再重新下载；
- 目标是符号链接、目录、其他非普通文件或不属于当前用户：该候选以脱敏的本地路径安全错误失败；工具不得跟随、读取、哈希、设置日期、移动、覆盖或删除它。

每次尝试目标前还要处理稳定同名的 `.part`：

- 不存在：正常开始；
- 是当前用户拥有的普通文件：先原样重命名为 `<name>.part.stale-<timestamp>`，再创建新的 `.part`；
- 是符号链接、非普通文件或不属于当前用户：该候选以脱敏的本地路径安全错误失败，不跟随、不覆盖也不删除。

这保证进程崩溃或强制终止留下的 `.part` 不会让同一目标在后续重试和重新运行中永久失败，同时保留旧内容供用户检查。

所有 `.invalid-*` 和 `.stale-*` 保留路径共用无覆盖分配规则：先尝试 `<timestamp>`，存在时依次尝试 `<timestamp>-1`、`<timestamp>-2`，直到获得未占用名称；移动操作必须使用不会覆盖已有目标的本地文件操作（例如同文件系统的独占 hard-link 后 unlink，或等价实现）。若无法安全获得或写入保留路径，则本候选失败，原文件保持不动。绝不使用会替换已有目标的普通 `os.replace` 来保存备份。

有效性最低要求与 Smoke 一致：大于 1 KiB、不超过 50 MiB、以 `FF D8` 开始。对工具已存在文件不重新计算或保存 URL。

不同 URL 即使下载后内容 SHA-256 相同也都保留，因为可能属于不同成长记录；终态额外统计“内容重复”，但不会删除第二份，也不会寻找替代候选。重复统计覆盖本轮全部成功和有效已有文件：下载成功项直接使用流式计算的内容 SHA-256；有效已有文件在本地读取并计算 SHA-256，不发起网络请求。每个哈希从第二次出现起增加一次“内容重复”计数。

## 下载与重试

确认后按首次发现顺序顺序下载，不并发。每个候选最多三次尝试：首轮一次，加最多两轮失败重试。重试队列只存在于内存中，且只包含本轮仍失败的候选。

两轮重试之间使用短暂固定等待；测试通过注入等待函数避免真实 sleep。每次尝试继续使用：

- 精确 CDN allowlist；
- Python 进程内 opener；
- 关闭代理；
- 拒绝重定向；
- 验证 HTTPS 证书；
- 120 秒网络超时；
- 50 MiB 上限；
- HTTP 200、`image/jpeg`、JPEG SOI 和最小大小检查；
- `.part` 写入、验证后原子改名。

首轮失败不阻塞其余候选。每轮只重试上一轮失败项。某项成功后立即从后续重试队列移除。

下载阶段按 `Ctrl-C` 时，当前 `.part` 必须删除，已完成文件保留，后续网络请求停止。终态报告成功、已存在、失败和未处理数量，不自动恢复。

## 终端输出和完成语义

允许显示：

- 设备和 App 是否就绪；
- 唯一候选总数；
- 当前下载进度的序号和总数；
- 本轮成功、已存在、失败、内容重复、日期设置失败、未处理数量；
- 本地输出目录。

禁止显示：

- 完整或部分 URL；
- URL path、provider ID 或远端 opaque filename；
- URL 哈希文件名；
- 可能包含 URL 的底层 HTTP 异常。

只有当本轮全部候选均为“成功”或“已存在”，且失败为 0、未处理为 0 时，工具才显示“本轮候选下载完成”。它不得显示“账号全量完成”。

## 错误处理

以下错误发生在下载确认前时停止，不创建图片：

- MuMu 未运行或运行实例不唯一；
- bundled ADB 不可用或连接失败；
- 鑫时光集 PID 不存在；
- logcat 子进程启动失败或异常退出；
- 未发现有效候选。

下载阶段的单项网络、HTTP、类型、大小或 JPEG 校验错误进入重试队列。输出目录、Git ignore 或权限前置检查失败则整批停止。`SetFile` 不存在或失败仅影响日期设置计数。

## 测试

所有自动测试使用合成日志、假子进程、假 opener 和临时目录，不访问真实 CDN，不包含真实照片 URL。

必须覆盖：

- 现有 18 个 Smoke 测试继续通过；
- 当前缓冲日志与后续流式日志都能被解析；
- URL 首次出现顺序和实时去重；
- `Ctrl-C` 正常终止、等待并清理 logcat 子进程；
- 子进程异常退出不进入下载；
- 只有准确输入 `DOWNLOAD` 才下载；
- 零候选和取消不创建输出目录；
- URL 日期的有效、无效、闰日和缺失情况；
- 稳定 SHA-256 文件名且终端不打印文件名；
- 有效已有文件跳过且不调用 opener；
- 损坏已有文件被保留后重新下载；
- 已有输出目录的 owner、mode 和符号链接边界；
- 最终 JPEG 只有在属于当前用户的普通文件时才可读取、复用或保留，危险类型不被跟随或修改；
- 遗留 `.part` 被保留为 `.stale-*` 后可继续下载，危险类型被拒绝；
- `.invalid-*` 与 `.stale-*` 名称碰撞时递增后缀且永不覆盖旧备份；
- 首轮失败继续、最多两轮重试、成功项不再重试；
- 不同 URL 的相同内容被保留并统计，且统计包含有效已有文件；
- `SetFile` 参数不包含 URL，日期失败不损坏 JPEG；
- 有效已有文件会重新尝试设置日期，使先前日期失败可自愈；
- 下载阶段中断清理当前 `.part` 并停止后续请求；
- stdout、stderr、异常文本、外部命令参数和持久化文件均不出现 URL；
- 输出目录和权限边界保持有效。

## 现场验收

1. 启动 MuMu 和已登录的鑫时光集家长版。
2. 运行 `python3 tools/export_originals.py batch`。
3. 确认启动后立即发现当前缓冲区候选。
4. 手动滚动列表，确认唯一候选计数继续增长。
5. 按 `Ctrl-C`，确认没有后台 logcat 子进程遗留。
6. 首次选择取消，确认没有新图片。
7. 再运行并准确输入 `DOWNLOAD`。
8. 验证多个文件下载成功，文件名包含日期且 URL 不出现在终端。
9. 在 Finder 中按创建日期和修改日期查看，确认成长日期正确。
10. 再次运行并滚动相同内容，确认已有文件被跳过且没有重复网络下载。
11. 终态能够区分成功、已存在、失败、内容重复、日期设置失败和未处理。
